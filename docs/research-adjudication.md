# Evidence-based Research Adjudication

> **设计文档（未实现）**：解决“多头/空头同时看似合理，如何避免最终答案和稀泥”的问题。

## 核心立场

**Agent 之间不以多数票或模型自报置信度决定结论。** 先拆分事实、解释与预测，再根据来源质量、口径、时间和估值敏感性裁决；无法裁决时明确弃权并给出下一项需要观测的证据。

## 输入合同

每个 Agent 必须提交一个标准化 `ResearchClaim`：

```json
{
  "claim": "示例：数据中心收入增长可能持续",
  "claim_type": "hypothesis",
  "horizon": "future 12 months",
  "supporting_evidence_ids": ["source-1"],
  "refuting_evidence_ids": ["source-2"],
  "key_assumptions": ["客户资本开支持续"],
  "falsification_conditions": ["相关资本开支持续下降"],
  "unresolved_questions": ["需求是否提前透支？"]
}
```

上述为**示意文本**，并非对 NVIDIA 当前财务表现的事实断言。

## 裁决顺序

1. **事实核验**：对齐原始公告/报表、财期、单位、币种、披露日期。删除或降级无来源的主张。
2. **命题归一**：把“看多增长”与“看空集中度”拆解成可独立验证的经营驱动，而非两个无法比较的口号。
3. **识别真正冲突**：例如双方是否对“未来一年收入增速”给出不兼容的假设？是否对同一事实作出不同解释？
4. **重要性评估**：用情景估值或现金流敏感性判断哪些变量真正影响结论；不以论述长度决定权重。
5. **补充检索**：对于关键冲突回到原始来源；缺乏数据则标记未决，不让模型虚构数字。
6. **条件式裁决**：输出当前更受证据支持的判断、关键条件、反证阈值、下次观测时间。

## NVIDIA 假想案例

| 观点 | 可检验问题 | 需要的数据 | 不得直接推断 |
| --- | --- | --- | --- |
| 多头：数据中心快速增长 | 增长持续多久？增长来自哪些需求？ | 已披露部门收入、公司指引、客户公开资本开支 | 高增长必然意味着股票低估 |
| 空头：客户集中度风险 | 风险集中在哪些客户及合同？ | 公司风险披露、公开客户信息 | 客户集中必然意味着下季业绩下滑 |
| 空头：毛利率见顶 | 毛利率变化来自定价、产品组合还是成本？ | 连续财报、管理层解释、合理比较期 | 一个季度回落代表永久拐点 |

### 最终报告合同

- **Current leading interpretation**：目前证据最强的解释（可为未决）。
- **Grounded facts**：核实事实及来源定位。
- **Disputed assumptions**：真正有分歧的可检验变量。
- **Sensitivity / scenarios**：变量变化如何影响结果（必须显式给出模型假设）。
- **Invalidation triggers**：什么证据出现会推翻当前判断。
- **Monitoring plan**：何时、从哪些来源更新证据。
- **Abstain when necessary**：关键数据不足时明确无法裁决。

## P2 验收条件

- 针对同一问题，至少两个 Agent 的主张可以映射到同一组 `ResearchClaim`。
- 裁决器能够检测数值冲突、来源缺失和财期口径不一致。
- 输出没有可核查证据的结论时必须失败或标记为未验证。
- 对 NVIDIA 假想案例输出“主判断 + 反证条件 + 下期监控指标”，不是机械罗列多空观点。
